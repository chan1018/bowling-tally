# ボウリング大会 集計ボード（bowling-tally）

14人・3ゲーム・2時間のボウリング大会を、**幹事1人がスマホ1台で**回すための当日ボード。
完全に端末内で完結する（サーバなし・アカウントなし・通信なし）。

- 用語の正本 → [CONTEXT.md](./CONTEXT.md)
- 設計判断の記録 → [docs/adr/](./docs/adr/)
- UI のデザイン契約 → [DESIGN.md](./DESIGN.md)（kimuz-web v1。`accent` のみボウリングの赤に差し替え）
- 設計メモ・運営メモの正本は Obsidian 側（`obsidian/input/アプリ設計/bowling-tally.md`）

## 使い方

1. **前日**：URL を開いて iPhone の共有ボタン →「ホーム画面に追加」
2. **前日**：ホーム画面のアイコンから開き、14人の呼び名を入れる
3. **当日**：必ず**ホーム画面のアイコンから**開く

> ⚠️ iOS では Safari のタブとホーム画面アイコンで保存領域が分かれることがある。
> 前日に Safari で名前を入れて当日アイコンから開くと**名前が消える**。
> アプリは今どちらで開いているかを画面下に表示するので、常に同じ側から開くこと。

## この設計の要点

**チーム分けは点数で組む。順位では組まない。**
勝敗判定は「チームの平均点」なのに、順位で蛇行させると平均点が揃わない
（上位2人が 200点・120点なら順位は隣でも実力差は80点）。
点数の高い順にスネークで配ったうえで、**平均差が縮む2人を入れ替え続ける**。
合計ではなく平均で比べるので、3人チームと4人チームが混ざっても人数差で不利にならない。

実測（14人・現実的な点数分布）: スネークのみ 8.17点差 → 入れ替え後 **0.83点差**。

**同じ点数なら必ず同じチームが出る。**
乱数の種を入力点数から導出しているため、ボタンを何度押しても結果は変わらない（[ADR-0002](./docs/adr/0002-deterministic-teams-and-hard-reunion-ban.md)）。

**2ゲーム目と3ゲーム目で同じ人とは組ませない。**
罰点ではなくハード制約。満たせない場合（欠席で人数が変わったとき）は黙って壊れず、画面に警告を出す。

**3ゲーム目は 1G+2G の点数で組む。**
運営メモは「2ゲーム目の順位だけ」と書いているが、それは手計算を避けるための制約だった（[ADR-0001](./docs/adr/0001-third-game-teams-use-both-games.md)）。

**伸び賞は表彰画面でも畳んである。**
先に知られると「2ゲーム目で手を抜いて最下位賞と伸び賞を両取り」が成立するため。

## データ

`localStorage` に自動保存（キー `bowling-tally-v2`）。
画面下の「データの書き出し・読み込み」で全データをテキスト化してコピーできる。
集計の区切りで自分宛に送っておけば、端末が死んでも復元できる。

## 開発

依存パッケージなし。`app/` の中身がそのままデプロイされる。

```bash
cd app && python -m http.server 8777    # http://127.0.0.1:8777/
```

検証は実ブラウザで行う（puppeteer-core + 実 Chrome）。
アルゴリズムの決定論・再会ゼロ・平均差、テンキーの実タップ可否、
localStorage の復元、横スクロール、13px未満の文字の有無まで確認する。
